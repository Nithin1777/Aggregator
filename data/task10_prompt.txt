LLM ACCESS MODEL (critical — read first):
  There is NO LLM API key available. LLM classification is done by an
  EXTERNAL AGENT HARNESS (Claude Code, Cursor, local agent, etc.) that
  the user points at a JSON file. The pipeline's job is:
    1. Extract unclassified gray pairs → data/not_sure.jsonl
    2. Write a self-contained prompt → data/NOT_SURE_PROMPT.md
    3. Read the harness's output file → validate → persist
  The pipeline NEVER makes LLM API calls. No SDK. No API key. No batching.
  The harness is the runtime; the pipeline is only I/O + validation.

ARCHITECTURE
  Stage 1: V2 matcher → bucket (confident_merge / confident_reject / gray)
  Stage 2: Gray pairs → data/gray_pairs.jsonl (disjoint from seed)
  Stage 3: Resolver --extract → data/not_sure.jsonl + NOT_SURE_PROMPT.md
  Stage 3b: User runs external harness → data/not_sure_classified.jsonl
  Stage 3c: Resolver --collect → validate → data/resolver_output.jsonl
  Stage 4: Seed validation (hash-based reuse if prompt unchanged)
  Stage 5: Merge labels → llm_labels table
  Stage 6: Live search reads llm_labels, falls back to V2

Live request path NEVER calls LLM. The harness runs out-of-band.

Create src/llm/bucketing.py:

    def bucket_pair(title_a, title_b, price_a, price_b,
                    mpn_a=None, mpn_b=None):
        """
        Return (bucket, merged, score, reason).
        bucket ∈ {confident_merge, confident_reject, gray}
        STRICT PRECEDENCE — do not reorder.
        """
        merged, score, reason = match_components_v2(
            title_a, title_b, price_a, price_b)

        # 1. MPN rescue: same MPN but matcher said no — escalate
        if mpn_a and mpn_b and mpn_a == mpn_b and not merged and score >= 0.5:
            return "gray", merged, score, reason

        # 2. Confident merge
        if merged and score >= 0.85 and "hard veto" not in reason.lower():
            return "confident_merge", merged, score, reason

        # 3. Confident reject
        if not merged and score < 0.55:
            return "confident_reject", merged, score, reason

        # 4. Everything else is gray
        return "gray", merged, score, reason

Report bucket fractions on the current candidate set.
Do NOT tune thresholds. If gray < 20% or > 60%, report and wait.

HARD RULES
═══════════════════════════════════════════════════════════════════
- No LLM API calls. No SDK import. No API key. The harness is external.
- No batch directories, no STATUS.json, no per-batch meta files. One
  extract file, one response file, one collect call.
- No modification to match_components_v2, can_merge, spec
  discriminators, guard rules, canonical logic, search ranking.
- No modification to data/judge_seed.jsonl or the 40 human labels.
- Resumable: --extract skips cached; --collect idempotent.
- pair_id = sha1(sorted(lower(title_a), lower(title_b)))[:16], no
  prefix, used everywhere (extract, collect, live search lookup, DB).
- Seed join is by titles, not pair_id.
- LLM "unsure" → leave unmerged in live search.
- Resolver-vs-human < 85% → STOP, do not wire live.
- Prompt rubric block MUST be byte-identical across:
    * judge round (source of 95% validation)
    * resolver template (src/llm/prompt_template.py)
    * NOT_SURE_PROMPT.md at extract time
  The hash check in Step 4 enforces this. If you change the rubric
  text, hash changes, and fresh seed validation is required.
- Do NOT touch scrapers, canonical ranking logic, or Python version.
- Do NOT ask clarifying questions. On ambiguous calls, choose the
  conservative option (leave unmerged, flag for review) and note it
  in the report.
