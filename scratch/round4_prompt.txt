FIX 2 — Response envelope (all tools, uniform)
═══════════════════════════════════════════════════════════════════

Every tool returns:

    {
      "ok": true,
      "data": {...},                          # tool-specific payload
      "total_matches": int,                   # total matching, pre-pagination
      "returned": int,
      "truncated": bool,
      "next_cursor": str | null,
      "filters_applied": {...},               # normalized echo
      "coverage": {                            # per filter key used
        "<key>": {"present": int, "of": int, "pct": float}
      },
      "warnings": [{"code": str, "message": str}],
      "server_version": str,
      "schema_version": str
    }

Errors use the same envelope with ok:false and no data:

    {
      "ok": false,
      "error_code": "unknown_filter_key" | "invalid_filter_value" |
                    "unsupported_operator" | "no_matches" |
                    "spec_not_extracted" | "internal_error",
      "message": str,
      "valid_keys": [...] | null,
      "suggestions": [{key, value} ...],      # nearest keys/enum members
      "details": {...},
      "server_version": str
    }

No bare ValueError. Every error is a structured response.

FIX 3 — unknown ≠ absent ≠ null (the core principle)
═══════════════════════════════════════════════════════════════════

Every search result and count result distinguishes:
  - filter_key_not_extracted: the key exists in catalog but has
    near-zero coverage → return warning with coverage %, do NOT
    return empty silently
  - filter_value_not_present: key exists with good coverage but the
    specific value matches nothing → return empty + suggestion list
    from enum with counts
  - filter_matched: normal results

Every product row in results includes:
  "specs": {
    "voltage": "12",                        # present
    "rpm": null,                            # not extracted
    ...
  }

null (not extracted) is distinct from absent (never in catalog) is
distinct from "0"/"" (extracted but empty). Never conflate.

FIX 4 — Input normalization + operators
═══════════════════════════════════════════════════════════════════

Accept units and aliases on input, store/compare canonical:
  "24V" / "24 v" / "24VDC"   → "24"
  "2.5kg-cm" / "2.5 kgcm"     → 2.5 (canonical unit kgcm)
  "5200 mAh" / "5.2Ah"        → 5200 (canonical unit mAh)
  "4S" / "4 s" / "4s lipo"    → "4s"
  "NEMA17" / "nema 17"        → "nema17"

Explicit operators (replaces string overloading):
  {"voltage": "12"}                              exact
  {"voltage": {"in": ["12","24"]}}               set
  {"rpm": {"gte": 150, "lte": 250}}              range
  {"rpm": {"eq": 200, "tolerance": 0.1}}         ±10%
  {"capacity_mah": {"gte": 5000, "lte": 5500}}   numeric range

Reject the old "150-250" string form with a suggestion showing the
operator form. Reject values with units in a form the normalizer
cannot parse, with a "did you mean" example in the error.

Validate `sort` against {relevance, price_asc, price_desc}; unknown
sort → error, not silent default.

FIX 5 — Add 4 new tools (DoD-aligned, nothing else)
═══════════════════════════════════════════════════════════════════

    @mcp.tool()
    def describe_catalog() -> dict:
        """
        Return everything an agent needs to know before querying:
        - total products, products by vendor, products by spec_category
        - spec_keys: [{key, type, unit, coverage_pct, count,
                       values (enum) | range (numeric)}, ...]
        - currency: "INR"
        - schema_version, server_version
        - freshness: {oldest_crawl, newest_crawl, per_vendor}
        Single call, replaces the sqlite3-by-hand discovery loop.
        """

    @mcp.tool()
    def describe_spec(key: str) -> dict:
        """
        Detail for one spec key. Explicitly distinguishes:
        - key_not_in_taxonomy: this attribute is not extracted at all
        - key_extracted_low_coverage: extracted but < N% coverage
        - key_healthy: normal
        Returns: type, unit, enum values with counts, min/max,
        coverage_pct, coverage_count, sample_raw_strings, warnings.
        """

    @mcp.tool()
    def count_components(
        filters: dict | None = None,
        query: str | None = None,
        price_max: float | None = None,
        in_stock_only: bool = False,
    ) -> dict:
        """
        Return {count, filters_applied, coverage, warnings}. No rows.
        Use before search_components to size a query. Distinguishes
        0 from "0 because filter key not extracted."
        """

    @mcp.tool()
    def get_product(product_id: int) -> dict:
        """
        Full record for one product:
        - all extracted specs (with confidence where applicable)
        - all vendor offers (price, stock, url, vendor_sku, mpn)
        - title, description, image_url, datasheet_url (if any)
        - crawl timestamps (when_scraped, when_specs_extracted)
        - spec_extraction_method: {key: 'regex'|'llm'|'manual'}
        Returns error envelope with error_code='product_not_found'
        if id doesn't exist.
        """
